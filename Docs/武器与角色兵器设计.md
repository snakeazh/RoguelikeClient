# 武器体系与「角色自带兵器」设计方案

> 状态：设计方案（未实现）。前置：P2-2 武器策略重构。
> 相关文件：`Assets/App/Config/BattleDefs.cs`、`Assets/App/Battle/WeaponRuntime.cs`、`Assets/App/Battle/BattleSession.cs`、`Assets/App/Battle/ChoiceService.cs`、`Assets/Res/Config/Battle/Weapons.json`

## 1. 现状盘点

### 1.1 数据

| 结构 | 关键字段 | 说明 |
| --- | --- | --- |
| `WeaponDef` | `Kind`、`MaxLevel=5`、`Damage/Cooldown/Projectiles/Range/Area/Speed/Pierce/ProjectileRadius/SplashRadius/Duration/SlowFactor` | `Area` 只用于光环/环绕刃/爆炸范围，弹体半径是 `ProjectileRadius` |
| | `DamagePerLevel/CooldownPerLevel/CountPerLevel/AreaPerLevel` | 每级线性成长 |
| | `PassiveId`、`EvolvedId` | 进化需要「武器满级 + 配套被动满级」 |
| | `Sprite`、`Mount` | 弹体精灵；`Mount=1` 生成随身炮台 |
| `Weapons.json` | 16 行 | 8 把基础（1~8）+ 8 把进化（101~108），进化形态不进掉落池 |
| `PassiveDef` | `Kind`（10 种）+ `Values[]` | 伤害/冷却/弹道数/范围/移速/生命/护甲/暴击/磁力/幸运 |

### 1.2 运行时

- `WeaponRuntime.cs`（757 行）：`TickWeapon` 里 `switch (weapon.Def.Kind)` 分 7 支（`Projectile/Homing/Orbit/Aura/Cleave/Chain/Bomb`），每支 30~80 行；随身炮台的 `_cannon/_cannonTarget/UpdateCannon` 也在这里。
- `BattleSession`：4 个武器槽 + 4 个被动槽、等级 20、暴击/冷却/范围等派生属性全部由被动叠出来。
- `ChoiceService`：三选一 = 升级池 + 新武器池 + 新被动池；规则是「保底一个升级项」「进化形态不进普通掉落」「满级武器 + 配套被动未满级时优先推被动」（进化保底）。
- 表现：HUD 只把武器拼成一行文本（`武器：长弓 Lv1  魔法炮 Lv2`），没有图标、没有"本命"概念。

### 1.3 角色

**目前没有"角色"这个概念。** `PlayerUnit` 直接读 `BattleSession` 的派生属性（`MaxHp = 100 × 被动`、`MoveSpeed = 5 × 被动`），开局空手，第一把武器只能靠三选一给。

## 2. 需求拆解

「角色自带兵器（例如弓箭或者刀）」= 每个角色有一把**开局就在、且长期跟着你**的武器。要回答四个问题：

| 问题 | 选项 | 建议 |
| --- | --- | --- |
| 占不占武器槽 | 占 1 槽 / 不占槽 | **不占槽**，否则开局就少一个 build 位，等于削弱 |
| 能不能升级 | 不能 / 能 | **能**，否则 3 分钟后它就是摆设 |
| 能不能进化 | 不能 / 能 | **能**，复用现有「满级 + 配套被动满级 + 宝箱」 |
| 不同角色是否不同 | 全员同一把 / 按角色 | **按角色**，这正是"角色自带"的意义 |

另外两个隐含需求：

- **叙事**：三选一里不该出现"获得一把弓"，因为你本来就有弓；但应该出现"弓 Lv2 → Lv3"。
- **手感**：本命武器是玩家每分钟都在用的东西，数值可以略低，但**冷却要短、判定要稳**（弓=远程点射、刀=近身扇形）。

## 3. 三个方案

### 方案 A：最小改法（Session 加"本命武器"）

`BattleSession` 增一个 `InnateWeapon` 实例与 `TryEquipInnate(def)`；`WeaponInstance` 加 `bool IsInnate`；槽位只数掉落武器；`ChoiceService` 的新武器池跳过已拥有的（`HasWeapon` 已覆盖）。

- 改动面：`BattleSession` + `ChoiceService` + `WeaponRuntime`（不判断来源，只是多一个实例）+ HUD 一行文本。
- 工期：**0.5 天**。
- 风险：没有角色表，过两天要加"第二个角色"时还得补 B。

### 方案 B：角色表（`CharacterDef` + 选人）

新增 `Characters.json`，`CharacterDef { Id, Name, InnateWeaponId, MaxHp, MoveSpeed, Sprite }`；`BattleLauncher.StartAsync(characterId)`；Home 加横向角色选择；`BattleSession.Character` 决定开局装备与基础属性。

- 改动面：A 的全部 + 新配置表 + 选人 UI + 存档（记住上次选择）。
- 工期：**1 天**（在 A 之上再加 0.5 天）。
- 风险：选人 UI 会牵动 Home 布局与 `DemoPrefabBuilder`，需要重新生成 Home 预制体。

### 方案 C：武器来源体系（`Source` + `Loadout`）

`WeaponDef.Source { Drop, Innate, Evolved }`，再加一个 `WeaponLoadout` 统一管理"装备了什么、从哪来、占几槽"，为以后"多角色 + 多武器池 + 装备界面"留口。

- 改动面：几乎所有武器相关代码 + 配置表 + UI。
- 工期：3~4 天。
- 结论：**现在做是过度设计**。等真的出现"武器池按角色区分 / 局外装备"再上。

### 推荐

**A 现在做，B 紧随其后，C 暂缓。** A 半天就能让"开局有弓"跑起来；B 只是把 `InnateWeaponId` 从常量搬进数据表 + 加一个选人界面，A 的运行时结构完全复用。

## 4. 推荐方案细节（A + B）

### 4.1 配置

`WeaponDef` 增一个字段：

```csharp
/// <summary>只能作为角色本命武器出现，不进三选一的新武器池。</summary>
public bool InnateOnly;
```

新增 `Assets/Res/Config/Battle/Characters.json`（`JsonUtility` 约束照旧：PascalCase、顶层数组、枚举写整数）：

| Id | Name | InnateWeaponId | MaxHp | MoveSpeed | 说明 |
| --- | --- | --- | --- | --- | --- |
| 1 | 游侠 | 1（长弓） | 90 | 5.4 | 远程点射，脆但灵活 |
| 2 | 剑士 | 3（大剑） | 125 | 4.6 | 近身扇形，血厚移速慢 |

`BattleSession` 现在把 `MaxHp = 100 × (1+被动)`、`MoveSpeed = 5 × (1+被动)` 写死，改成 `Character.MaxHp × (1+被动)`、`Character.MoveSpeed × (1+被动)`，默认角色 Id=1，找不到表时退回 100/5。

### 4.2 运行时

```csharp
// BattleSession
public CharacterDef Character { get; }
public WeaponInstance InnateWeapon { get; private set; }
public bool IsInnate(int weaponDefId) => InnateWeapon != null && InnateWeapon.Def.Id == weaponDefId;
internal void EquipInnate()   // Begin 时调用一次
{
    var def = WeaponDef.Get(Character.InnateWeaponId);
    InnateWeapon = new WeaponInstance(def) { IsInnate = true };  // 不加入 _weapons
}
```

- **槽位**：`CanAddWeapon` 仍看 `_weapons.Count < 4`，本命武器不进 `_weapons`，所以「本命 + 4 把掉落武器」= 5 把同时生效。
- **战斗循环**：`WeaponRuntime.Tick` 遍历 `session.Weapons` 之后再单独 Tick 一次 `session.InnateWeapon`（它没有 `WeaponInstance.Level` 之外的差异，复用同一套 behavior）。
- **升级**：`ChoiceService` 的升级池加 `session.InnateWeapon` 一项；`Session.TryUpgradeWeapon` 已经能处理任意实例。
- **进化**：`CanEvolve/FindEvolvable` 加对本命武器的检查；进化后 `IsInnate` 保留，HUD 仍显示 `[本命]`。
- **三选一**：新武器池跳过 `def.InnateOnly`；由于本命武器不在 `_weapons` 里，`HasWeapon` 不会误判，需要额外 `session.IsInnate(def.Id)` 过滤。

### 4.3 表现

- HUD：`本命：长弓 Lv2` 单独一段（或 `★ 长弓 Lv2` 放武器行首），其余武器沿用现有文本。
- 结算面板：武器清单里把本命武器放第一位并标 `★`。
- 选人界面：Home 里两个角色卡片（名称 + 本命武器图标 + 一句定位），点击后写 `BattleSettings.SelectedCharacter`（`PlayerPrefs`/`ISaveService`），下次默认选中。

### 4.4 数值

| 项 | 建议 |
| --- | --- |
| 本命武器 Lv1 伤害 | 普通武器 Lv1 的 **0.85 倍** |
| 本命武器冷却 | 普通武器 **×0.9**（手感更顺） |
| 满级 | 同样 5 级，可进化 |
| 开局体验 | 前 30 秒只靠本命武器也能清掉前两波（哥布林 14 血 / 2.2 秒出一只） |

## 5. 与 P2-2（武器策略重构）的关系

**顺序必须是先 P2-2，再本命武器。** 理由：现在加本命武器，要么在 `switch` 里再写一套"如果是本命就……"的分支，要么把 `WeaponRuntime.Tick` 复制一份；等 `IWeaponBehavior` 拆完，本命武器只是"另一个 `WeaponInstance`"，零特殊分支。

P2-2 之后，加东西的成本：

| 想加的东西 | 成本 |
| --- | --- |
| 一把新武器（已有形态） | 改 `Weapons.json` 一行，**10 分钟** |
| 一种新武器形态（例如回旋镖往返、地雷） | 新增一个 `IWeaponBehavior` 实现（80~150 行）+ 注册表一行，**2~4 小时** |
| 一个角色的本命武器 | `Characters.json` 一行 + `Weapons.json` 一行，**10 分钟** |
| 一个新角色 | `Characters.json` 一行（+ 选人界面已有），**10 分钟** |

## 7. 风险

1. **槽位语义变化会让强度上升**：本命不占槽 = 多一把武器，`MaxWeaponSlots` 名义 4 实际 5。需要同步看波次密度（`Waves.json`）或把 Boss 血量回调一点，避免 5 分钟变得太轻松。
2. **进化保底会被本命武器挤占**：`ChoiceService.evolutionPity` 现在遍历 `session.Weapons`，要加上本命武器，并决定优先级（建议：本命武器进化优先级**低于**掉落武器，避免玩家想凑的 build 被本命抢选项）。
3. **选人 UI 牵动预制体**：Home 现在由 `DemoPrefabBuilder` 生成，加卡片要改生成器并重跑 `Tools/Client/Rebuild Demo Assets`，注意 `.meta` 与 `UIReference` 的 key 一起更新。
4. **存档兼容**：`BattleRecords` 已用 `battle.meta.*.v1` 前缀，角色选择建议 `battle.character.selected.v1`；老存档没有该键时默认角色 1，不要抛异常。

## 8. 不做的事（当前阶段）

- 不做局外武器解锁/装备界面（那是 C 方案的事）。
- 不做武器词条/随机品质（会把 16 行配置膨胀成几百行，且与"每级线性成长"冲突）。
- 不做角色技能（冲刺已经是唯一的主动技能，加技能要重做输入与 HUD）。
