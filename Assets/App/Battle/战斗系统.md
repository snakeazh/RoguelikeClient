# 战斗系统（类幸存者骨架）

单局 5 分钟、竖屏单手、自动攻击。数值和内容全部走 json 配置，战斗内角色用 2D 精灵
（`Assets/Res/Battle/Sprites`，缺失时自动退回纯色几何占位），**不包含**局外成长树、正式 UI 皮与音频资源。
玩法来源见策划文档《卡牌战争·类幸存者玩法设计》。

## 1. 运行方式

- 场景：`Assets/Scenes/Main.unity`（只挂了一个 `AppBootstrap`）。
- 首页点「开始战斗」→ `HomeViewModel.StartBattleCommand` → `BattleLauncher.StartAsync()`。
- 命令行自测：`Unity.exe -batchmode -projectPath <工程> -executeMethod App.EditorTools.BattleSmokeTest.Run`
  （Play 模式自动开一局，4 倍速跑到 40 秒，断言有击杀且升过级，然后自己退出，返回码 0）。
  可选参数：`-battleSeconds 300 -battleSpeed 20 -battleImmortal 1`，跑完整 5 分钟并测试三个 Boss 与结算界面
  （`-battleImmortal 1` 把玩家血量每帧拉满，只为了走完流程，不代表难度）。

## 2. 代码结构

| 文件 | 职责 |
| --- | --- |
| `BattleRunner.cs` | 唯一的 MonoBehaviour，主循环：输入 → 玩家 → 刷怪 → 敌人 → 武器 → 弹体 → 拾取 → 升级 → 胜负（`partial` 拆成 `.Input`/`.Combat`/`.Pickups`/`.Spawns`/`.Damage`/`.Flow`/`.Camera` 七个分部） |
| `BattlePhase.cs` | 流程状态机：`Idle/Running/LevelUp/Paused/Ending/Finished` + `BattlePhaseRules.CanTransition` 转移表 |
| `DamageInfo.cs` | 一次伤害的描述：`Amount` + `Crit`，`Scaled()` 给溅射/连锁衰减，`Plain()` 给不会暴击的伤害 |
| `BattleSession.cs` | 一局的纯数据：时间、等级、经验、血量、击杀、金币、武器/被动实例、派生属性（伤害/冷却/范围/暴击…）与进化判定 |
| `BattleInput.cs` | 触摸/鼠标输入；左半屏动态摇杆 + 右下冲刺；也提供 `AutoPlay/AutoMove/AutoDash` 给冒烟测试。分界线按 `Camera.pixelRect`（游戏画面）算，不按窗口算 —— 宽屏有黑边时摇杆仍在画面左半边 |
| `PlayerUnit.cs` | 移动、冲刺（2.5 身位 / 0.2s / 无敌 0.3s / CD 3s）、减速状态 |
| `EnemyUnit.cs` | 7 种行为 + 精英词缀 + Boss 阶段二，全部由一个类按 `EnemyDef.Behavior` 分支 |
| `EnemySpawner.cs` | 读 `Waves.json` 的时间轴，按 Spawn/Elite/Ring/Tide/Boss/Rest 触发；分钟成长曲线也在这里 |
| `WeaponRuntime.cs` | 7 种武器形态：直线/追踪投射物、环绕刀刃、持续光环、扇形剑气、连锁闪电、定时炸弹；含弹道数/冷却/伤害成长与进化后的形态；`Mount = 1` 的武器还负责生成并驱动随身炮台 |
| `CannonRig.cs` | 魔法炮 / 湮灭炮的随身炮台：站玩家侧面、炮管自动转向、蓄能光球 + 收缩能量环、开火后座与炮口闪光 |
| `ProjectileUnit.cs` | 玩家与敌方弹体共用，圆形命中、穿透、小范围爆炸 |
| `PickupUnit.cs` | 经验糖/蛋糕/金币/宝箱/磁力/炸弹/沙漏 |
| `ChoiceService.cs` | 升级三选一的候选生成（武器新/被动新/升级三池各一 + 进化保底）与应用 |
| `TransientFx.cs` | 一次性特效：圆形闪光（爆炸）与矩形剑气，用 `unscaledDeltaTime` 淡出，不影响游戏逻辑 |
| `BattleVisuals.cs` | 精灵/预制体缓存：`LoadAsync` 预载、`GetSprite`、`Spawn`（按预制体建节点）、`Body`（给实体铺 SpriteRenderer）、`CreateMap`（平铺地面 + 四周墙）；缺资源时静默退回占位 |
| `BattleMap.cs` | 地图尺寸与边界：`Width = 18`、`Height = 36`、`WallThickness = 0.62`，以及 `Walkable`、`ClampToWalkable` |
| `CameraFollow.cs` | 相机跟随玩家（`SmoothDamp` 0.12s），并夹在地图边界内，地图比视野小时居中 |
| `PlaceholderArt.cs` | 运行时生成圆形/方形/三角形/圆环贴图，纯色占位（精灵缺失时的兜底） |
| `BattleRecords.cs` | 局外记录：累计金币、出战次数、胜利次数、最高击杀、最长存活（存档键 `battle.meta.*.v1`） |
| `BattleLauncher.cs` | 战斗入口服务：关首页 → 建 runner → 开 HUD；结算后清场回首页 |
| `UI/Battle/*` | HUD、升级三选一、结算三个界面（View 只做绑定） |

界面预制体：`Assets/Res/UI/Battle/{BattleHud,LevelUp,BattleResult}.prefab`，由
`Tools/Client/Rebuild Demo Assets` 生成。所有键名写在对应 View 的注释里。

### 2.1 2D 精灵

- 相机：`Main Camera` 正交、`orthographicSize = 5`（竖屏 9:16 时可见 5.63 × 10 世界单位），
  2D 世界单位 1 = 1 个精灵宽度。相机由 `BattleRunner.SetupMap()` 在开局时设置，运行期跟着玩家走。
- 资源：`Assets/Res/Battle/Sprites/*.png`（33 张，含 `shadow`/`tile_floor`/`wall_h`/`wall_v`），
  显示用预制体 `Assets/Res/Battle/Prefabs/{Player,Enemy,Projectile,Pickup,Blade}.prefab`。
  重新生成：`Tools/Client/Rebuild Battle Sprites`（`App.EditorTools.BattleSpriteBuilder.RebuildAll`）。
- 运行期：`BattleLauncher.StartAsync()` 里 `await BattleVisuals.LoadAsync(resources)` 预载，
  之后 `BattleRunner` 用 `BattleVisuals.Spawn` 建实体、用 `BattleVisuals.Body` 铺 SpriteRenderer。
- 排序（`sortingOrder`）统一在 `Assets/App/Battle/BattleSort.cs`，**不要在别处写死数字**：
  地面 -100、墙 -98；角色（玩家/敌人/影子/光环）不是固定值，而是按世界 y 分档
  （`BattleSort.Character(y, instanceId)`，y 越低越靠前，同一档位用实例 id 低两位分 4 个子槽）——
  角色 40–327、影子 = 所属角色的档位下沿、光环再低 1；拾取物 400、炮台 410–414、
  环绕刃 420、炸弹 422、弹体 440、剑气/闪光 450 起（`TransientFx` 的 `order` 参数是相对 450 的偏移）、
  闪电 456、伤害飘字 470。
  为什么要按 y 排：精灵用同一个 `sortingOrder` 时，Unity 会再按「到相机的距离」决定先后；
  相机跟着玩家跑，两个重叠的怪的前后关系就会逐帧互换，看起来像在闪。按 y 分档后顺序只跟位置有关。
- 哪个敌人/弹体用哪张图由配置决定：`Enemies.json` 的 `Sprite`、`Weapons.json` 的 `Sprite`
  （相对 `Battle/Sprites/` 的名字，不带扩展名）。留空则用默认图（敌人 `enemy_goblin`、弹体 `proj_orb`）。
- 回旋刃专用图：`blade.png`（128×128）是木纹回旋镖，V 形两臂 + 深棕描边 + 木纹 + 臂上刻蜥蜴，
  `+Y` 是外抛方向，所以 `TickBlades` 把它朝外旋转看起来像在飞；画法见 `BattleSpriteBuilder.Blade/PaintLizard`
  （`LizardContains` 里调身体/头/尾/四条腿的尺寸，`PaintLizard` 的 `t`/`facing` 调位置与朝向）。
  显示直径用 `size * 3.0f`（`WeaponRuntime.SyncBlades`）。
- 大剑刀光：`slash_arc.png`（256×256）是一张 120° 的月牙弧，弧心在贴图正中、朝 `+X` 张开。
  `TransientFx.Fan()` 把它按 `angleDegrees` 旋转后铺在玩家身上，直径 = `2 * radius`（贴图外缘正好是精灵半径），
  0.26 秒内张开 1.08 倍并淡出。弧带径向 80%→100%、角度两端收细，改粗细/亮度看
  `BattleSpriteBuilder.SlashArc`（`inner` / `radial` 指数 / `taper` 指数 / `alpha` 系数）；
  没有这张图时会退化成 `TransientFx.Swipe` 的细剑气，不会没反馈。
- 换美术：把同名 PNG 覆盖进 `Sprites/`（Sprite 单张导入、`Pixels Per Unit = 图片边长`，即 1 张图 = 1 世界单位），
  不需要改代码；完全删掉 `Assets/Res/Battle` 也能跑，只是退回纯色几何。

### 2.2 朝向

所有战斗贴图都是**朝上（+Y）**画的，所以「朝向」统一按 `atan2(方向.y, 方向.x) - 90°` 旋转：

- 弹体：`ProjectileUnit.ApplyFacing()` 跟着 `_velocity` 转（箭、剑气这类长条贴图不会永远朝上飞），
  额外自转由 `_spinAngle` 叠加。
- 玩家：`PlayerUnit.UpdateFacing()` 只转 `Body` 子节点（不转根节点，否则阴影/光环会跟着歪），
  按移动方向或冲刺方向 `Slerp`。
- 敌人：`EnemyUnit.FaceDirection()` 让贴图上方始终对着玩家，怪不会全部朝一个方向。
- 环绕刃：`WeaponRuntime.TickBlades` 每帧按当前角度朝外旋转，看起来像风车。
- 换新贴图时注意：有明确「正前方」的图（箭、炮口、角色脸）必须按朝上画，否则朝向会差 90°。

### 2.3 地图与相机

战场是一张 **18 × 36 世界单位** 的大地图，比一屏（5.63 × 10）大得多，镜头跟着玩家滚动：

- 尺寸在 `BattleMap.cs` 里改（`Width` / `Height` / `WallThickness`），`Walkable` 是扣掉墙厚后的可走矩形。
- 地面用 `tile_floor` 以 `SpriteRenderer.drawMode = Tiled` 平铺（不是拉伸一张大图），
  所以地图再大也只有一张 64×64 贴图；四周墙用 `wall_h` / `wall_v` 平铺，厚度 `WallThickness`。
- 玩家移动、冲刺、拾取判定都以 `_walkable` 为界（`Player.Tick(..., walkable)`），撞墙即停。
- 相机：`CameraFollow.Configure(player, _arena)`，`LateUpdate` 里 `SmoothDamp` 跟随并夹在地图内；
  玩家走到地图边缘时镜头停住，露出墙。
- 刷怪：`BattleRunner.RandomSpawnPosition()` 沿射线找到「当前屏幕可见区」的边沿再向外 0.9，
  夹进可走区并确认仍在视野外 —— 怪不会当着玩家的面凭空出现，也不用从很远的地方走过来。
  Boss 固定刷在玩家正上方的屏幕外。
- 竖屏保护：`BattleRunner.ApplyAspectGuard(camera)` 在开战与「窗口尺寸变化」时把游戏相机限制成
  **9:16 的中间一列**（`camera.rect`，两侧留黑）。原因：宽屏下 `orthographicSize × aspect`
  会大于地图半宽（18/2 = 9），`ClampAxis` 的 min > max 退化成「永远居中」，镜头就**不再横向跟随**了。
  注意 `camera.aspect` 在设置 `rect` 之后会变成**视口内**的宽高比（0.5625），用它做判断会每帧在
  「加黑边 / 去黑边」之间反复横跳、看起来还是不动；所以比例一律用 `Screen.width / Screen.height` 算。
  `CameraFollow.ClampToBounds()` 与 `CameraView()` 都用 `Screen 比例 × camera.rect.width` 折算真实可见宽度。
  桌面包在 `AppBootstrap.ApplyDesktopWindow()` 里强制按 `540 × 960` 竖屏窗口打开（`UNITY_STANDALONE`），
  并在构建设置里关掉 `defaultIsNativeResolution`，避免记忆到 4K 全屏。
- 改地图大小后不需要动 UI：HUD 是屏幕空间 Canvas（`UIRoot`），不随相机移动。

### 2.4 受击反馈

打击感全部在 `BattleRunner` 的 `DamageEnemy` / `DamagePlayer` / `KillEnemy` 三个方法里接线，
不影响任何伤害计算：

| 反馈 | 实现 | 触发点 |
| --- | --- | --- |
| 伤害飘字 | `DamagePopup.Show(worldPos, amount, crit, color)`，固定 48 个 3D TMP 复用，先快后慢上浮 + 弹出缩放 + 淡出 | 敌人中招白字、暴击金字加 `!`、玩家受伤红字 |
| 敌人闪白 + 挤压 | `EnemyUnit.PlayHitFeedback()`：`_body.color` 向白插值、`localScale` 放大 14%，0.09 秒衰减 | 敌人非致死受伤 |
| 敌人击退 | `EnemyUnit` 内 `_knockback` 向量按 `Exp(-14·dt)` 衰减后叠加到 `position`（Boss 不击退） | 敌人非致死受伤 |
| 命中火花 | `TransientFx.Flash()`：运行时生成的柔和圆斑（`SoftCircle()`），0.1 秒放大 1.5 倍并淡出 | 命中、死亡爆散（更大更久） |
| 玩家闪红 | `PlayerUnit.FlashHurt()`：`Body` 颜色向 `(1, 0.42, 0.42)` 插值 72%，0.22 秒恢复 | 玩家受伤 |
| 屏幕泛红 | `HurtOverlay`：Hud 层全屏 `Image` + 运行时生成的径向渐变图，`Pulse(strength)` 后按 4.2/秒衰减，最大透明度 0.45 | 玩家受伤，伤害越高越明显 |
| 镜头震动 | `CameraFollow.Shake(amplitude, duration)`：在平滑后的位置上叠加随机偏移，取最大值不叠加 | 玩家受伤 |

- 数值都在方法里写死，改手感直接调常数（`DamagePopup` 的 `Lifetime/RiseDistance/FontSize`、
  `HurtOverlay` 的 `DecaySpeed/MaxAlpha`、`BattleRunner` 里 `Pulse(0.2f + severity * 0.4f)`）。
- `DamagePopup` / `HurtOverlay` / `TransientFx` 都用 `Time.unscaledDeltaTime`，暂停或结算时仍会正常播放并消失。
- 暴击由 `WeaponRuntime.RollDamage()` 直接返回 `DamageInfo { Amount, Crit }`，一路作为参数传到
  `DamageEnemy` / `ProjectileUnit` / `ExplodeAt`（暴击时数值 ×2、飘字金色加 `!`），不再有"先写字段再读回来"的旁路。
  溅射与连锁衰减用 `DamageInfo.Scaled(0.5f / 0.85f)`，暴击标记跟着走；敌人接触、自爆、场景炸弹用 `DamageInfo.Plain()`。

### 2.5 随身炮台（魔法炮 / 湮灭炮）

`Weapons.json` 里 `Mount = 1` 的武器不再由玩家本体放技能，而是在身边生成一门炮台，
由 `CannonRig`（`Assets/App/Battle/CannonRig.cs`）负责表现，`WeaponRuntime` 负责驱动：

| 环节 | 实现 |
| --- | --- |
| 生成 | `WeaponRuntime.UpdateCannon()`：背包里存在 `Mount = 1` 的武器就 `CannonRig.Create(player.transform)`，没有就 `Destroy` |
| 位置 | 永远站在「开火线的侧面」（炮管朝向的垂直方向，`SideDistance = 1.02`），所以不会挡在弹道上；`localPosition` 用 `Vector3.SmoothDamp`（`MoveSmoothTime = 0.26`）平滑，另加 `sin` 上下浮动 |
| 自动瞄准 | `WeaponRuntime` 每帧锁定最近敌人（带粘性：目标活着且仍在 `Range * 1.25` 内就不换目标，避免两只敌人之间来回摆），交给 `CannonRig.AimAt()`；炮管用 `Mathf.SmoothDampAngle`（`AngleSmoothTime = 0.22`、`MaxTurnSpeed = 200` 度/秒）转向 —— 是加速-减速的弧线，不会一帧甩到位；没目标时保持上一次朝向、炮口不发光 |
| 蓄能 | `1 - CooldownTimer / Cooldown` 作为进度传给 `CannonRig.SetCharge()`：炮口光球由 0.22 长到 0.82、由蓝白变纯白并闪烁；外圈能量环从 1.15 收缩到 0.3；进度 > 0.7 时炮口轻微抖动 |
| 开火 | `TickShooter` 里 `Mount == 1` 时**不再瞬间对准**：比较真实炮管方向 `BarrelDirection` 与目标的夹角，小于 `FireAlignment = 14` 度才从 `MuzzlePosition` 射出（超时 `CannonFireGrace = 0.6` 秒则先打）；发射后 `CannonRig.Kick()` 触发 0.18 的后座位移 + 0.1 秒炮口闪光 |
| 美术 | `Battle/Sprites/cannon.png`（炮管，朝 +Y）与 `cannon_base.png`（底座），由 `Tools/Client/Rebuild Battle Sprites` 生成；缺图时退回 `PlaceholderArt.Square/Ring` |

调参入口：`CannonRig` 顶部的 `BarrelLength / MuzzleOffset / BarrelDiameter / SideDistance / AngleSmoothTime / MaxTurnSpeed / MoveSmoothTime / MaxMoveSpeed`
（想更慢更飘就加大 `AngleSmoothTime`、降低 `MaxTurnSpeed`），以及 `Update()` 里蓄能尺寸 `Lerp(0.22f, 0.82f, v)` 和能量环 `Lerp(1.15f, 0.3f, v)`；
开火对准宽容度在 `WeaponRuntime` 的 `FireAlignment / CannonFireGrace`。

### 2.6 流程状态机

一局战斗的阶段收敛在 `Assets/App/Battle/BattlePhase.cs`，**只有 `BattleRunner.SetPhase()` 能改**，
转移是否合法由 `BattlePhaseRules.CanTransition(from, to)` 决定；非法转移只打
`[Battle] illegal transition X -> Y, ignored` 并保持原状态，不会抛异常打断协程。

| 阶段 | 含义 | 模拟 |
| --- | --- | --- |
| `Idle` | `Begin` 前 / 已销毁 | 停 |
| `Running` | 正常战斗 | **推进** |
| `LevelUp` | 三选一面板（连升时连续停留） | 停 |
| `Paused` | 玩家或系统暂停（切后台、以后的 ESC 菜单） | 停 |
| `Ending` | 已分胜负：清场、写记录、等结算面板关闭 | 停 |
| `Finished` | 结算面板已关，准备退回首页（终态） | 停 |

允许的转移：

```
任意      -> Idle        （销毁）
Idle      -> Running
Running   -> LevelUp | Paused | Ending
LevelUp   -> LevelUp | Running            （连升；不允许直接进 Ending）
Paused    -> Running | Ending             （暂停菜单里"退出战斗"）
Ending    -> Finished
```

- 判断「能不能推进模拟」统一用 `runner.IsSimulationPaused`（= `Phase.BlocksSimulation()`），不要再自己拼布尔。
- 升级：`RunLevelUpAsync()` 用 `while (Session.CanLevelUp && Phase == LevelUp)` 一次吃完所有待升级，
  面板关掉后不再靠下一帧重新进入（旧写法会漏跑一帧推进）。
- 结算：`EndAsync()` 用 `SetPhase(Ending)` 当重入锁（`Phase` 状态本身就是锁），重复调用会被规则拒绝。
- 暂停接口：`RequestPause()` / `RequestResume()`；`OnApplicationPause(true)` 在移动端自动暂停
  （桌面窗口失焦故意不暂停，否则批处理冒烟和截图会卡在暂停态）。
- 订阅 `PhaseChanged(from, to)` 可以在不改流程代码的前提下加"暂停中"提示、埋点或调试面板。

## 3. 配置表

`Assets/Res/Config/Battle/*.json`，由 `ConfigTables.LoadAsync` 在启动时读入：

- `Enemies.json`：`Behavior` 0=Chaser 1=Runner 2=Tank 3=Shooter 4=Exploder 5=Splitter；
  Shooter 用 `AttackInterval/AttackRange/ProjectileSpeed`，Exploder 用 `FuseTime/ExplodeRadius`，
  `SlowOnHit` 是接触减速时长，`Sprite` 是敌人贴图名（相对 `Battle/Sprites/`，留空用 `enemy_goblin`）。
  **`Id >= 100` 一律按 Boss 处理**（100 最终 Boss，101/102 小 Boss）。
- `Weapons.json`：`Kind` 0=Projectile 1=Orbit 2=Homing 3=Aura 4=Cleave 5=Chain 6=Bomb；
  `Projectiles` 是基础弹数（不是 `Count`，避免和 `ConfigRowBase.Count` 撞名），`ProjectileRadius` 是弹体半径，
  `Sprite` 是弹体/刀刃/光环的贴图名（相对 `Battle/Sprites/`，留空用默认），
  `DamagePerLevel/CooldownPerLevel/CountPerLevel/AreaPerLevel` 是每级成长，
  `EvolvedId` 指向进化后的武器 Id（0 表示不可进化），`PassiveId` 是配套被动。
  Id 1–8 是基础武器，101–108 是进化武器（不出现在三选一里）。

**大剑（Kind=4 Cleave）不受索敌影响**：每次冷却到点就朝玩家当前**面向方向**挥一刀，
命中「半径 `AreaOf(weapon, Area)` 内、且与面向夹角 ≤ `CleaveSpread / 2`」的所有敌人，
同时在该方向放一道月牙刀光。`WeaponRuntime` 顶部常量 `CleaveSpread = 120f` 就是扇形总角度
（改小更窄更快、改大更宽更钝），刀的朝向由 `PlayerUnit.FacingDirection` 决定
（停下后保持最后朝向，开局朝上）。
- `Passives.json`：`Kind` 0..9 对应伤害/冷却/弹数/范围/移速/生命/护甲/暴击/磁力/幸运，`Values` 是每级数值。
- `Waves.json`：`Kind` 0=Spawn 1=Elite 2=Ring 3=Tide 4=Boss 5=Rest；`Affix` 0=None 1=Swift 2=Giant 3=Split 4=Shell 5=Frenzy；
  `SpawnCount` 是每次刷出的数量（不是 `Count`）。当前手感基线：怪物 `Speed` 已整体减半（0.7–1.9），
  普通波 `SpawnCount` 为原始的 2 倍（首波 6 只/2.2s、环形 36 只、潮水 12 只），精英与 Boss 仍各 1 只；
  想再加密只改 `SpawnCount`（同时调小 `Interval`），想让怪更快就改 `Enemies.json` 的 `Speed`。
  刷怪点在「视野外一圈」，`BattleRunner.RandomSpawnPosition()` 里 `distance + 0.45f` 控制离屏幕多远。
- `Levels.json`：升到下一级所需经验，`Id=1` 表示 1→2 级。

进化配对（`Weapons.json` 的 `EvolvedId` / `PassiveId`）：

| 武器 | 进化后 | 需要满级的被动 |
| --- | --- | --- |
| 长弓 | 穿云弓 | 备用箭袋 |
| 回旋刃 | 千刃轮 | 大弹弓 |
| 大剑 | 断罪巨剑 | 力量耳环 |
| 魔法飞弹 | 星陨飞弹 | 急速药丸 |
| 魔法炮 | 湮灭炮 | 瞄准镜 |
| 雷电法典 | 天罚法典 | 幸运草 |
| 定时炸弹 | 炼狱炸弹 | 小圆盾 |
| 权能法杖 | 神权法杖 | 轻灵之靴 |

> 雷电法典（`Kind=5 Chain`）的表现在 `WeaponRuntime.TickChain`：先打最近的敌人，再以 `Area`（跳跃半径）
> 向未命中的敌人连锁，每跳伤害 ×0.85、最多 8 跳。每一跳都会用 `LightningFx.Bolt(from, to, ...)`
> 画一条带抖动的电弧（`LineRenderer`，0.15s 左右淡出），起点是玩家、之后在敌人之间串联，
> 颜色越靠后越暗；`LightningFx` 的材质用 `Sprites/Default` + `Texture2D.whiteTexture`，
> 少了白图会采样成黑色、在深色地面上完全看不见。进化后的天罚法典走同一套代码。

> 魔法炮 / 湮灭炮（`Mount = 1`）不是从玩家身上射出的：身上会多一门自动瞄准的炮台，
> 弹体从炮口出膛，冷却期间炮口蓄能发光（见 2.5）。`Mount` 是新增字段，写 json 时别忘补上。

> JsonUtility 的约束：字段名必须和 C# 完全一致（区分大小写），枚举写成整数，顶层必须是数组，
> **新增字段必须补进 json**（JsonUtility 不跑字段初始化器，缺字段会变成 0）。
> 中文文件必须存成 UTF-8，否则会解析失败。

## 4. 数值锚点（当前实现）

- 玩家 HP 100、移速 5 身位/s、接触伤害 10 / 0.5s。
- 受击后 0.6s 无敌（`BattleRunner.PlayerHitInvulnerability`）：没有它，被人群包住时一帧会被结算十几次。
- 敌人 HP 每分钟 ×1.4，伤害每分钟 ×1.2（`EnemySpawner.HpScale/DamageScale`）。
- 经验值随分钟成长（`BattleRunner.ExpScale`，0 分钟 ×1，5 分钟 ×10），否则按策划的升级曲线到不了 20 级。
- 升级时回 15% 血；小蛋糕 4% 掉落、恢复 30%。
- 冲刺距离 2.5 身位、0.2s、无敌 0.3s、CD 3s，可以穿怪。
- 武器冷却最低 0.12s；暴击 ×2；索敌带权重（Boss ×2.5、精英 ×1.6）。
- 时间轴：90s 首个精英、150s 环形包围、180s 小 Boss 石像鬼王、225s 潮水、240s 双精英、
  250s 小 Boss 深渊领主、268s 最终 Boss 巨形史莱姆（1700 血）。
- 两个小 Boss 只掉宝箱、不结束对局；只有最终 Boss 死亡才算胜利。
- Boss 半血后移速 ×1.35 并每 3 秒放 12 发环形弹；30 秒未击杀进入狂暴（`BossRageTime`）。
- 时间到 300s：Boss 已死算胜利，Boss 还活着算超时失败。
- 宝箱：优先触发进化，其次升级一把未满级武器，再次补一把新武器（Id < 100），否则 +50 金。
- 参考结果（20 倍速自动跑满 5 分钟，`-battleImmortal 1`）：557 杀、20 级、274s 击杀最终 Boss 通关；
  途中触发过「回旋刃 → 千刃轮」进化；不开无敌的机器人能活到 300s 但通常打不掉 Boss，结算为超时失败。

## 5. 怎么往下长

- **加一把武器**：`WeaponKind` 加枚举 → `Weapons.json` 加一行 → `WeaponRuntime.Tick` 里加一个分支
  （新形态写一个 `TickXxx`）。UI 不用改，HUD 读的是 Session 里的实例列表。
- **加一种敌人**：`EnemyBehavior` 加枚举 → `Enemies.json` 加一行 → `EnemyUnit.Tick` 的 `switch` 加分支。
- **加波次**：直接往 `Waves.json` 加行，无需改代码。
- **加进化**：基础武器填 `EvolvedId` + `PassiveId`，进化武器单独一行（Id ≥ 100）即可，代码不用改。
- **换美术**：替换 `PlaceholderArt.CreateRenderer` 调用处的 sprite，或把 `EnemyUnit` 的渲染物换成 prefab；
  战斗逻辑不依赖渲染物类型。
- **还没做**：局外成长（永久属性/解锁）、战斗内暂停菜单、声音、正式 UI 皮、武器图鉴。
